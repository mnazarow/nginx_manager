# 03. Установка, обновление и удаление

## Требования

| Компонент | Минимум | Рекомендуется |
|---|---|---|
| ОС | Debian 11, Ubuntu 20.04, RHEL/Rocky/Alma/Oracle 8, CentOS Stream 9, Fedora 38 | Debian 12/13, Ubuntu 24.04, RHEL 9 |
| CPU | 1 ядро | 2+ ядра |
| Память | 512 МБ | 1–2 ГБ (статистика держит последние минуты в памяти) |
| Диск | 500 МБ свободно | 5+ ГБ для истории запросов на нагруженном сервере |
| Python | 3.9 (ставится автоматически) | 3.11+ |
| nginx | 1.18 | 1.24+ (stable/mainline с nginx.org) |
| Доступ | root (sudo) | — |
| Сеть | порты 80/443 доступны из интернета для сайтов и Let's Encrypt | порт панели закрыт снаружи, вход через домен панели с HTTPS |

Установщик сам поставит: `nginx`, модуль `stream` (`libnginx-mod-stream` / `nginx-mod-stream`), `certbot`, `openssl`,
`logrotate`, `python3` с `venv`, а также Python-зависимости: FastAPI, uvicorn, pydantic, psutil.

## Установка

```bash
# 1. Скопируйте архив на сервер и распакуйте
scp nginx-manager-1.9.0.tar.gz root@server:/root/
ssh root@server
tar xzf nginx-manager-1.9.0.tar.gz && cd nginx-manager

# 2. Запустите установку
sudo ./install.sh
```

Через 1–3 минуты (зависит от скорости зеркал пакетов) появится сводка:

```
Установка завершена.

  Веб-панель:  http://203.0.113.10:8088/
  Логин:       admin
  Пароль:      Kq7mR2xa9vTe4n83!
               (сгенерирован; сохранён в /root/nginx-manager-credentials.txt)
```

Откройте адрес в браузере, войдите и **смените пароль** (раздел «Мой профиль»).

### Что делает установщик

1. **Проверка системы**: ОС и менеджер пакетов, архитектура, память, свободное место, занятость порта панели.
2. **Пакеты**: обновление индекса, установка nginx (из дистрибутива или с nginx.org), модуля stream, certbot,
   Python. На RHEL-системах при необходимости подключается EPEL (Oracle Linux — `oracle-epel-release-elN`,
   остальные — `epel-release` из дистрибутива, а если его там нет — пакет с сайта Fedora) и ставится
   Python ≥ 3.9. Репозиторий nginx.org подключается с `skip_if_unavailable=1`: если он временно недоступен,
   обновления системы и установка других пакетов не ломаются.
3. **Python-окружение**: копирование программы в `/opt/nginx-manager`, создание `venv`, установка зависимостей
   (3 попытки при сетевых сбоях), проверка импорта.
4. **Каталоги и конфигурация**: `/etc/nginx-manager/panel.conf`, `/var/lib/nginx-manager/*` с правильными правами,
   каталог кэша, **резервная копия исходного `nginx.conf` → `nginx.conf.nm-orig`**, команда `nmctl`,
   `logrotate`, юнит systemd, лимит открытых файлов для nginx (`LimitNOFILE=65535`).
5. **Безопасность ОС**: при SELinux Enforcing — `httpd_can_network_connect`, метки каталогов и порта stub_status;
   открытие 80/443 (TCP) и 443/UDP (HTTP/3) в ufw или firewalld; поиск конфликтующих веб-серверов (Apache, httpd,
   lighttpd, Caddy) с предложением их остановить.
6. **Администратор**: создание пользователя (если пользователей ещё нет).
7. **Применение конфигурации nginx**: nginx переходит под управление панели. Если применение невозможно (например,
   порт 80 занят), nginx остаётся с прежней конфигурацией, а причина показывается — установка продолжается.
8. **Запуск сервиса** и ожидание ответа `/healthz` (до 40 с).
9. **Диагностика** (`nmctl diag --problems`) — сразу видно, что требует внимания.

Повторный запуск `install.sh` безопасен: он работает как «восстановление» (переустанавливает программу и
зависимости, сохраняя данные, `panel.conf` и пользователей).

Подробный журнал: `/var/log/nginx-manager-setup.log`.

### Параметры install.sh

| Параметр | По умолчанию | Описание и рекомендации |
|---|---|---|
| `--port N` | `8088` | Порт веб-панели. Выбирайте свободный порт, не 80/443. |
| `--bind ADDR` | `0.0.0.0` | Адрес панели. `127.0.0.1` — панель доступна только локально (через SSH-туннель или через домен панели в nginx) — **рекомендуется для рабочих серверов**. |
| `--admin-user NAME` | `admin` | Имя первого администратора. |
| `--admin-password PW` | случайный | Пароль администратора (≥ 8 символов, буквы разного регистра, цифры). Если не задан — генерируется и сохраняется в `/root/nginx-manager-credentials.txt` (права 600). |
| `--le-email EMAIL` | — | E-mail для Let's Encrypt (предупреждения об истечении). Можно задать позже в настройках панели. |
| `--nginx-repo REPO` | `distro` | `stable` или `mainline` — установить nginx из официального репозитория nginx.org (новее, со встроенным stream и, для mainline, HTTP/3). |
| `--no-firewall` | — | Не трогать ufw/firewalld. |
| `--open-panel-port` | — | Открыть порт панели в firewall (по умолчанию не открывается — безопаснее). |
| `--with-geoip` | — | Установить пакет `maxminddb` для определения стран (базу нужно положить отдельно, см. раздел 09). Включается автоматически, если в `/var/lib/nginx-manager/geoip/` уже лежит файл `.mmdb` (например, при переустановке с сохранёнными данными). |
| `--wheels DIR` | — | Офлайн-установка зависимостей Python из каталога wheel-файлов. |
| `--python PATH` | авто | Использовать конкретный интерпретатор Python ≥ 3.9. |
| `--no-apply` | — | Не применять конфигурацию nginx при установке (nginx остаётся как был; применить позже кнопкой или `nmctl apply`). |
| `--no-start` | — | Не запускать сервис. |
| `-y`, `--yes` | — | Не задавать вопросов (для автоматизации). |

**Примеры:**

```bash
# Полностью автоматическая установка для Ansible/cloud-init
sudo ./install.sh --yes --admin-password 'Str0ng!Passw0rd' --le-email ops@example.com

# Панель только локально, nginx mainline с nginx.org
sudo ./install.sh --bind 127.0.0.1 --nginx-repo mainline

# Другой порт панели с открытием в firewall
sudo ./install.sh --port 9443 --open-panel-port
```

### Офлайн-установка (без доступа к PyPI)

На машине с интернетом и той же версией Python:

```bash
pip download -r requirements.txt -d wheels/
pip download -r requirements-optional.txt -d wheels/   # если нужен GeoIP
```

Перенесите каталог `wheels/` вместе с программой и запустите:

```bash
sudo ./install.sh --wheels /root/nginx-manager/wheels
```

Системные пакеты (nginx, certbot, python3-venv) в этом случае должны быть доступны из локального зеркала ОС.

### Установка в контейнере или без systemd

Если systemd не обнаружен, сервис запускается в фоне (`setsid nohup …`, журнал `/var/log/nginx-manager.log`) без
автозапуска. Для контейнеров рекомендуется запуск командой
`/opt/nginx-manager/venv/bin/python -m app.main` как основного процесса (nginx при этом запускается панелью сам —
сторож следит, чтобы он работал).

## Первый вход

1. Откройте `http://IP:8088/` и войдите.
2. **Мой профиль** → смените пароль, включите двухфакторную аутентификацию.
3. **Настройки панели → Let's Encrypt** — укажите e-mail.
4. **Диагностика** — убедитесь, что нет ошибок (красных пунктов).
5. **Сайты → Добавить сайт** — см. [04. Быстрый старт](04-quick-start.md).

### Доступ к панели по HTTPS (рекомендуется)

1. Создайте DNS-запись `panel.example.com` → внешний IP сервера.
2. **Сертификаты → Добавить** → Let's Encrypt для `panel.example.com`.
3. **Настройки панели → Сеть**: домен панели `panel.example.com`, сертификат — выпущенный. Сохраните и примените.
4. Откройте `https://panel.example.com/`.
5. Закройте прямой доступ к порту 8088: в `/etc/nginx-manager/panel.conf` задайте `NM_BIND_HOST=127.0.0.1`
   и выполните `systemctl restart nginx-manager`.

### Файл /etc/nginx-manager/panel.conf

| Параметр | По умолчанию | Описание |
|---|---|---|
| `NM_BIND_HOST` | `0.0.0.0` | Адрес, на котором слушает панель. |
| `NM_BIND_PORT` | `8088` | Порт панели. |
| `NM_DATA_DIR` | `/var/lib/nginx-manager` | Каталог данных (БД, сертификаты, копии). |
| `NM_NGINX_CONF` | `/etc/nginx/nginx.conf` | Главный файл nginx, которым управляет панель. |
| `NM_MANAGED_DIR` | `/etc/nginx/nginx-manager` | Каталог сгенерированной конфигурации. |
| `NM_LOG_DIR` | `/var/log/nginx` | Где nginx пишет журналы панели. |
| `NM_CACHE_DIR` | `/var/cache/nginx/nginx-manager` | Каталог зон кэша. |
| `NM_STUB_STATUS_PORT` | `8089` | Локальный порт stub_status (только 127.0.0.1). |
| `NM_NGINX_BIN` | авто | Путь к исполняемому файлу nginx. |
| `NM_LOG_LEVEL` | `info` | Уровень журнала сервиса: `debug`, `info`, `warning`, `error`. |
| `NM_TLS_CERT`, `NM_TLS_KEY` | — | HTTPS для самой панели без nginx (пути к PEM-файлам). |
| `NM_TRUST_PROXY` | `127.0.0.1,::1` | Адреса прокси, которым панель доверяет X-Forwarded-For (для определения IP пользователя). |
| `NM_SECRET_KEY` | авто | Секрет сервиса (генерируется в `/var/lib/nginx-manager/.secret_key`). |
| `NM_DISABLE_COLLECTOR` | `0` | `1` — отключить сбор статистики (для отладки). |

После изменения: `systemctl restart nginx-manager`.

## Обновление

```bash
tar xzf nginx-manager-1.9.0.tar.gz
sudo ./nginx-manager/update.sh --yes
# или из архива напрямую:
sudo /opt/nginx-manager/update.sh --archive /root/nginx-manager-1.9.0.tar.gz
```

Порядок работы `update.sh`:

1. Проверка, что новая версия новее установленной (иначе нужен `--force`).
2. **Резервные копии**: база данных и экспорт настроек (`nmctl backup`), архив кода текущей версии
   (`/var/lib/nginx-manager/backups/code-<версия>-<дата>.tar.gz`), копия `nginx.conf`.
3. Остановка сервиса, замена кода (виртуальное окружение сохраняется), обновление зависимостей.
4. Обновление юнита systemd, `nmctl`, `logrotate`.
5. Миграция схемы базы данных (автоматически, без потери данных).
6. Запуск и ожидание `/healthz` до 60 с.
7. **При любой ошибке на шагах 3–6 — автоматический откат** к предыдущей версии из архива кода и запуск.
8. Переприменение конфигурации nginx генератором новой версии (с обычной проверкой и откатом) — можно отключить
   параметром `--no-apply`.
9. Диагностика.

| Параметр | Описание |
|---|---|
| `--source DIR` | Каталог с распакованной новой версией (по умолчанию — каталог, где лежит скрипт). |
| `--archive FILE` | Архив `.tar.gz` с новой версией. |
| `--wheels DIR` | Офлайн-установка зависимостей. |
| `--no-backup` | Не делать резервных копий (не рекомендуется). |
| `--no-apply` | Не переприменять конфигурацию nginx. |
| `--with-geoip` | Установить пакет `maxminddb` (статистика и доступ по странам), если его ещё нет. Уже установленный пакет обновляется всегда; если в каталоге данных есть база `.mmdb`, пакет ставится и без параметра. |
| `--force` | Обновить на ту же или более старую версию. |
| `-y`, `--yes` | Без вопросов. |

## Удаление

```bash
sudo /opt/nginx-manager/uninstall.sh            # сервис удаляется, данные сохраняются
sudo /opt/nginx-manager/uninstall.sh --purge -y # удалить всё
```

Порядок работы:

1. Остановка сервиса — чтобы копия базы была согласованной (панель не пишет в неё во время архивации).
2. **Финальная резервная копия** `/root/nginx-manager-final-backup-<дата>.tar.gz` (БД, настройки, конфигурация).
   Архив доступен только root (права 600): в нём хеши паролей, секреты каналов и закрытые ключи загруженных
   сертификатов. Если архивация не удалась, скрипт предупреждает и показывает путь к журналу.
3. Удаление сервиса, юнита systemd, лимитов nginx.
4. **Конфигурация nginx** — один из вариантов:
   - по умолчанию: восстанавливается исходный `nginx.conf` из `nginx.conf.nm-orig`, проверяется `nginx -t` и
     выполняется reload. Если исходная конфигурация не проходит проверку — остаётся конфигурация панели (сайты
     продолжают работать), а исходная лежит рядом для ручного исправления;
   - `--keep-nginx-config`: текущая сгенерированная конфигурация «замораживается» в `/etc/nginx/nginx-manager-frozen`
     и продолжает работать без панели — удобно, если вы больше не хотите пользоваться панелью, но сайты должны
     работать.
5. Удаление программы, `nmctl`, `logrotate`.
6. С `--purge` — удаление данных, настроек, кэша, журналов `nm-*.log`. Сертификаты и каталог ACME сохраняются,
   если nginx продолжает их использовать.

| Параметр | Описание |
|---|---|
| `--purge` | Удалить данные панели (БД, статистику, копии, загруженные сертификаты), журналы. |
| `--keep-nginx-config` | Оставить nginx работать с текущими сайтами без панели. |
| `--remove-nginx` | Удалить пакет nginx. |
| `--remove-le-certs` | Удалить сертификаты Let's Encrypt, выпущенные панелью (`certbot delete nm-*`). |
| `--no-backup` | Не создавать финальную резервную копию. |
| `-y`, `--yes` | Без вопросов. |

## Проверка установки

```bash
nmctl status          # состояние сервиса, nginx, версии конфигурации
nmctl diag -p         # только проблемы
systemctl status nginx-manager
journalctl -u nginx-manager -f
curl -s http://127.0.0.1:8088/healthz
```
