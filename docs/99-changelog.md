# История версий

Обновление на новую версию: `sudo ./update.sh` из каталога с новой версией (подробно — в главе
[03](03-installation.md)). Перед обновлением делается резервная копия, при ошибке запуска выполняется откат.

## 2.12.0

**Тесты для всего проекта и нетиповые ситуации: около 250 новых тестов (покрытие кода 81 → 88 %), проверки на случайных данных с живым nginx, обход всех методов API; исправлено почти 30 ошибок, найденных тестами** ([16](16-troubleshooting.md#применение-конфигурации))

Исправления (поведение в редких, но реальных ситуациях):

- **Списки угроз DShield** блокировали только первый адрес каждой сети (`x.x.x.0`), а не всю сеть `/24` — строки
  «начало конец маска» теперь разбираются целиком. Обновите списки кнопкой «Обновить» в «Защите».
- **Применение конфигурации** больше не падает с «open() … failed», если удалены файлы вне версий (блокировки, доступ
  по ссылке, списки угроз, адреса роботов, сети стран) — они создаются пустыми и заполняются при обновлении.
- **Подключённый sites-enabled с сервером по умолчанию** (файл `default` в Debian/Ubuntu): заглушка панели уступает
  ему порт с предупреждением; сайт «по умолчанию» на том же порту — понятный отказ вместо ошибки nginx -t.
- **IPv6 «включён», а в системе его нет** — nginx слушает только IPv4 с предупреждением (раньше nginx не запускался);
  пояснение к ошибке «socket() [::]:80 failed (97)».
- **Проверка браузера:** адрес возврата с табуляцией или переводом строки (`/\t/evil.example`) больше не уводит на
  чужой сайт.
- **Самопроверка защиты:** молчащий сервер и ошибка TLS считаются ошибкой проверки, а не «запрос заблокирован».
- **Сбор статистики:** позиция чтения журнала сохраняется и при остановке панели между чтениями (строки последних
  секунд больше не считаются дважды после перезапуска); повреждённая запись статистики не ломает графики, сводку и
  анализ; строка запроса с `\` и кавычками в журнале ошибок nginx (сканеры) разбирается; записи `[emerg]` без
  известной категории — «Ошибка конфигурации»; Microsoft Office и CryptoAPI больше не определяются как ChromeOS.
- **Журнал ModSecurity:** запись больше 16 МБ не останавливает чтение журнала; поля неожиданного типа не прерывают
  обработку.
- **Поиск по журналам:** `%` и `_` в запросе — обычные символы; неверное число в `start`, `end`, `min_rt` — понятная
  ошибка 400.
- **REST API:** границы периода `nan`, `inf` и вне 1970–2100 — ошибка 400; `points=0` больше не даёт ошибку 500;
  отрицательный `limit` больше не означает «все записи».
- **Вход в панель:** клиенты IPv4 при панели на адресе `::` (`::ffff:198.51.100.7`) проверяются по сетям IPv4
  «Доступа к панели» и доверенных прокси; пароль из одних заглавных букв не принимается.
- **Блокировки:** адреса самого сервера (127.0.0.0/8, ::1) не блокируются — через них работают самопроверка и
  проверка выпуска сертификатов.
- **Сертификаты:** цепочка, вставленная в обратном порядке (промежуточный первым), исправляется сама.
- **Диагностика:** правила ufw со списками и диапазонами портов (`80,443/tcp`, `8000:8100/tcp`), профили «Nginx
  HTTP/HTTPS», правила только для подсети не считаются «открыто для всех»; диапазоны портов firewalld; «Открыть порты»
  проверяет номера, сообщает о неудаче команды и об отсутствии брандмауэра.
- **Копии:** повреждённый `.gz` — понятная ошибка при загрузке, восстановлении и скачивании из хранилища; копия
  настроек, обрывающаяся внутри архива, и архив больше 512 МБ — понятный отказ.
- **nmctl:** запрос пароля без терминала (cron) и повреждённая база — сообщение и подсказка вместо трассировки.
- **panel.conf:** `export`, кавычки, комментарий в конце строки и CRLF понимают и панель, и скрипты установки и
  обновления; неверное число — понятная ошибка при запуске.
- **Уведомления:** длинные сообщения в Telegram обрезаются до предела (раньше Telegram их отклонял); повреждённый
  канал не мешает отправке отчёта в остальные.
- Остановка сервиса дожидается отмены фоновых задач (без ошибок «cannot schedule new futures» в журнале);
  соединение со stub_status закрывается и при мусорном ответе; в интерфейсе «1 с» вместо «1 000 мс», отрицательные
  длительности — «0 с».

Тесты (`tests/test_edge_*.py`, `tests/js/`):

- **Нетиповые ситуации по всему проекту:** конвейер применения (nginx -t не принял черновик или итог, reload не
  прошёл, nginx упал после reload, live — обычный каталог, чистка версий, параллельные применения), сборщик на
  настоящих файлах (ротация, усечение, удаление, обрыв строки, хвост 300 МБ), проверки бэкендов на настоящих сокетах
  (мусор, таймаут, unix-сокет, самоподписанный HTTPS), диагностика в окружениях «голый сервер», «RHEL с firewalld и
  SELinux», «Ubuntu с ufw», Telegram (поддельные и устаревшие кнопки, чужой чат), nmctl, скрипты установки.
- **Свойства на случайных данных (hypothesis):** значения, принятые проверками полей, не добавляют директив; строка в
  кавычках доходит до клиента без изменений через запущенный nginx; случайные комбинации переключателей сайта,
  глобальных настроек и настроек панели проходят nginx -t (60 примеров в обычном прогоне, `NM_FUZZ=N` — сколько
  угодно).
- **Все методы API:** без входа — только публичные, наблюдатель ничего не меняет, пустые, мусорные и враждебные
  данные — ответ 4xx с пояснением, ни одной ошибки 500.
- Зависимости для разработки — `requirements-dev.txt`; покрытие — `pytest --cov=app`.

  прямо из него (`…/latest` — последняя копия).
- **Смена ключа подписи списков без перерыва:** до трёх открытых ключей у списка, подходит подпись любым.
- REST API: 206 методов (новый — «Что изменится» перед восстановлением).

**Подпись списков адресов (Ed25519), перенос потоков и общих настроек nginx между серверами, продление сертификатов, полученных «Забрать сюда», проверка копий настроек, восстановление из второго хранилища в панели** ([05](05-sites.md#подпись-списка-ed25519), [17](17-bans.md#сравнение-конфигурации-серверов), [15](15-backup-versions.md#проверка-копий))

- **Подписанные списки адресов:** у списка по ссылке (сайта и доверенных адресов) — открытый ключ Ed25519 владельца;
  загрузка принимается, только если подпись из файла `.sig` верна. Список может меняться, а подменить его без
  закрытого ключа нельзя. Ключи и подпись — `nmctl lists keygen | sign | verify` или OpenSSL 3; проверка подписи
  встроена в панель (без сторонних библиотек), «Проверить» до применения проверяет и подпись.
- **Сравнение серверов:** «Отправить туда» / «Забрать сюда» для TCP/UDP-потоков (по адресу, порту и протоколу) и

- **Сертификаты, полученные кнопкой «Забрать сюда»,** продлеваются на источнике и приходят сами, если источник знает
  этот сервер; если не знает — предупреждение с подсказкой.
- **Проверка копий настроек** раз в N дней и кнопкой: последняя копия на сервере и в хранилищах открывается паролем,
  контрольные суммы, настройки, пары «сертификат — ключ», свежесть копии; результат — в карточке и в «Диагностике»,
  ошибка — в уведомлениях о событиях.
- **Второе хранилище копий настроек:** список копий и «Восстановить…» прямо в панели; копии настроек из основного
  хранилища скачиваются как есть (пароль спросит окно восстановления).
- REST API: 205 методов (новые — перенос потоков и общих настроек, проверка копий, список и скачивание копий из второго
  хранилища).

  настройки возвращаются автоматически. В консоли — `nmctl settings backup | inspect | restore`.
- **Списки адресов по ссылке** в «Доступе по IP» сайта: файл со списком (текст, CSV, JSON — адреса находятся сами)

- **Уведомление об использовании ссылки для доступа:** отметка «Сообщить, когда воспользуются» у ссылки — событие
  сразу уходит в каналы уведомлений при любом уровне, в Telegram — с кнопкой «Закрыть доступ».
- **Сравнение с другим сервером:** кнопка «Сравнить» во вкладке «Другие серверы» — сайты и потоки только здесь,
  только там и с различиями (по вкладкам), поля настроек nginx и защиты, доверенные адреса, сертификаты с разными
  доменами или сроками. Передаются только отпечатки разделов, без адресов бэкендов и секретов.
- **Перенесённый сертификат без источника:** диагностика предупреждает, если сертификат, перенесённый с другого
  сервера, скоро истекает, а продлённый не пришёл или сервер-источник давно не выходит на связь; кнопка «Выпустить
  сертификат здесь» выпускает сертификат с теми же доменами и переключает на него сайты.
- Источник событий «Доступ по IP (ссылки, временный доступ, списки адресов)» в «Уведомлениях о событиях»;
  заголовки уведомлений сохраняют регистр аббревиатур (IP, GeoIP).
- REST API: 192 метода (новые — копия настроек: создание, проверка, восстановление, разделы; списки адресов:
  статус, обновление, проверка ссылки; сравнение с сервером).

  применения конфигурации сайты последней применённой версии уходят на этот сервер и применяются там: новые
  создаются, изменённые обновляются (по номеру у источника — смена доменов не создаёт дубликат), удалённые и
  исключённые удаляются (только созданные синхронизацией), сертификаты пересылаются, только когда новые или продлены.
  На получателе такие сайты помечены, в карточке — предупреждение; приём можно выключить.
- **Отказы «Доступа по IP»:** сценарии анализа «Отказы с адресов рядом с разрешёнными» (похоже, у своего сменился
  адрес) и «Много отказов „Доступа по IP“» (97 сценариев), метрика оповещений «Отказов „Доступа по IP“», счётчик
  Prometheus `nm_http_ipaccess_denied_requests_total` и линия «доступ по IP» в панели Grafana «Отклонённые
  запросы».
- **nmctl:** `nmctl os` (срок поддержки ОС, код возврата для мониторинга), `nmctl peers` (связь и обмен с другими

  `*.example.com` и для серверов, закрытых от интернета, выпускаются прямо из панели. Учётные записи DNS-провайдеров —
  Cloudflare, DigitalOcean, Linode, OVHcloud, Route 53, Google Cloud DNS, свой DNS-сервер (RFC 2136: BIND, PowerDNS,
  Knot, Windows DNS) и свои скрипты для любого провайдера. Панель показывает, установлен ли плагин certbot, и ставит
  его кнопкой; секреты хранятся в файлах с правами 600 и не показываются в интерфейсе.
- **Выбор центра сертификации** ([07](07-certificates.md#центр-сертификации)): Let's Encrypt, ZeroSSL, Google Trust
  Services или свой ACME-сервер (step-ca, Smallstep, Vault PKI) с привязкой аккаунта EAB и доверенным корневым
  сертификатом. Сертификат продлевается в том центре, где выпущен; центр виден в списке.
- Короткие сертификаты (сутки у step-ca, 6–45 дней у ACME-профилей) продлеваются за треть срока, а не за 30 дней —
  иначе они продлевались бы при каждой проверке. Сроки проверяются ежечасно (было — раз в 6 часов); после неудачного
  продления — пауза до 6 часов, чтобы не упираться в лимиты центра. Предупреждения диагностики и анализа, оповещение
  «Сертификат скоро истечёт» учитывают срок действия: для коротких сертификатов тревога — только если продление
  действительно опаздывает; оставшееся время показывается в часах.
- Диагностика: certbot установлен, но не запускается (сертификаты молча перестают продлеваться); не установлен
  плагин DNS-провайдера (кнопка «Установить плагин»); выбран центр без адреса или ключа EAB.
- Подсказки к ошибкам выпуска: TXT-запись не найдена, токен отклонён, зона не найдена, ошибки TSIG, EAB, TLS
  ACME-сервера.
- Экспорт и импорт переносят учётные записи DNS и ссылки сертификатов на них.
- Инструмент скриншотов сообщает адрес каждого ответа с ошибкой (раньше в консоли было только «404» без адреса).
- Автотестов 102 (было 90); все проходят на Python 3.9 и 3.13.

**Проверено**

- Сквозной тест `tools/acme_e2e.py` против тестового ACME-сервера Pebble и DNS-сервера BIND: выпуск с
  HTTP-проверкой, wildcard с DNS-проверкой через RFC 2136, подключение wildcard к сайту и проверка сертификата,
  который отдаёт nginx, продление с новым серийным номером, привязка EAB (HMAC-ключ скрыт в журнале).
  До этого выпуска путь Let's Encrypt проверялся только по частям.

**Исправления**

- Мастер нового сайта: регулярные выражения и `.example.com` больше не попадают в запрос сертификата; для
  wildcard-домена мастер сразу объясняет, что нужна DNS-проверка.

## 1.6.0

Выпуск посвящён проверке всего кода: новые автотесты (фаззинг всех маршрутов API, импорт конфигурации nginx,
сборщик статистики, оповещения, сертификаты, консоль `nmctl`) нашли и закрыли ошибки, перечисленные ниже.

**Безопасность**

- Политика входа проверяется сервером, а не только интерфейсом: пользователь с временным паролем и администратор
  без 2FA (при включённом «Требовать 2FA для администраторов») могут только смотреть и настраивать свой профиль;
  изменения, в том числе через API, и создание API-токена отклоняются с кодом 403 ([12](12-security.md)).
  Включить требование 2FA можно, только настроив 2FA себе.
- «Свои директивы»: оператор больше не может добавить директивы, которые читают или создают файлы от root или
  выполняют код (`include` произвольного файла, журналы вне `/var/log/nginx`, временные каталоги, Lua, Perl, njs) —
  раньше через `include /etc/shadow` и ошибку `nginx -t` можно было прочитать чужой файл, а через журнал в
  `/etc/cron.d` — выполнить команду от root. Наблюдатель больше не может запускать `nginx -t` для черновика
  сайта ([12](12-security.md#безопасность-сервиса-в-системе)).
- Код 2FA принимается один раз: повторно использовать подсмотренный код нельзя.
- Вход отвечает одинаково (и по тексту, и по времени) на неизвестное имя и на неверный пароль.
- Непредвиденная ошибка сервера больше не раскрывает подробности в ответе — только тип ошибки и где смотреть журнал.
- Финальная резервная копия при удалении (`uninstall.sh`) создавалась с правами 644 — теперь 600: в ней хеши
  паролей, секреты каналов и закрытые ключи. Копия делается после остановки сервиса, поэтому база в ней согласована.

**Исправления**

- Оповещения: правило без выбранных каналов отправляло уведомления во все каналы — теперь, как и описано, только в
  панель; в тексте уведомления вместо номера сайта — его название; пропуск данных (нет запросов, сайт выключен)
  больше не считается восстановлением и не порождает пары «Восстановлено → Сработало» ([11](11-alerts.md)).
- Импорт существующей конфигурации nginx падал на директивах без аргументов (например, `proxy_pass;` в шаблоне).
- Сборщик статистики: строка журнала с JSON неожиданной формы (не объект, вложенные значения, код ответа вне
  100–999) могла остановить разбор пачки — теперь она учитывается как ошибка разбора.
- `nmctl`: ошибки выводятся понятным текстом с кодом возврата 1 вместо трассировки Python; импорт полностью
  проверяет файл (в том числе записи пользователей) до изменения базы, повреждённый файл не меняет ничего
  ([14](14-cli-api.md)).
- `GET /api/requests/live` игнорировал параметр `seq`.
- Регулярный отчёт: в строке «Запросов: 12,3 тыс., …» точка сокращения превращалась в запятую.
- Дашборд: пока первая проверка бэкенда не прошла (сразу после запуска), карточка «Бэкенды» писала «все доступны» —
  теперь «проверяется: N».
- Журнал аудита: запись о действии над сотнями сайтов раздувала таблицу — теперь в записи не более 50 имён, а длинные
  детали в интерфейсе сворачиваются; у всех действий понятные подписи.
- WebSocket: неверное сообщение от браузера больше не обрывает соединение, фильтр живого журнала проверяется;
  ограничение доступа к панели по IP применяется и к WebSocket.
- Фоновые задачи (диагностика, сети стран, продление сертификатов, отчёты, автоматическая копия) выполняются
  независимо: сбой одной записывается в «События» и не откладывает остальные. Сбой записи истории проверок бэкендов
  больше не останавливает сами проверки.
- Python 3.9 (RHEL 8/9): примитивы asyncio создаются внутри цикла событий; весь набор тестов проходит на 3.9 и 3.13.
- Активные проверки бэкендов: задачи проверок теперь удерживаются до завершения (раньше теоретически могли быть
  удалены сборщиком мусора на середине проверки).

**Установка и диагностика**

- SELinux: диагностика проверяет метки всех портов, которые займёт nginx (сайты, HTTP/3, потоки, `stub_status`), и

- RHEL-семейство: EPEL для Oracle Linux и запасной источник EPEL; репозиторий nginx.org с

**Документация и качество**

- Полный справочник REST API — все 116 методов с ролями и описанием — собирается из кода
  ([14](14-cli-api.md#все-методы)); описания попали и в Swagger UI.
- Автотесты следят, чтобы справочники в документации совпадали с кодом, а ссылки на разделы и картинки не были битыми.

  импорты в интерфейсе убраны.

- **Документация в панели**: поиск по всем главам с подсветкой, оглавление главы с отслеживанием прокрутки,
  ссылки на разделы, переход к соседним главам, печать в PDF, увеличение скриншотов.
- **Справка по странице**: кнопка «?» в верхней панели и клавиша F1 открывают нужный раздел документации
  в боковой панели. Щелчок по значку «i» у любого поля открывает описание именно этого параметра.
- Автономная HTML-версия документации: `python3 tools/build_docs_html.py`.
- Автотесты ядра: `python3 -m pytest -q tests/`.

**Улучшения**

- Сборщик статистики обрабатывает журнал порциями и отдаёт управление между ними: при всплесках трафика и
  дочитывании накопившегося журнала после перезапуска панель и графики не «замирают». Производительность разбора
  с детектором блокировок — около 30 000 строк журнала в секунду на одно ядро.
- Адреса внешних сервисов (Telegram API, webhook, сервис определения внешнего IP) принимают только `http(s)://`.
- Скриншоты и подписи в документации дополнены, схема прохождения запроса исправлена.

**Исправления**

- Права на файлы конфигурации: при установке с ограничивающей umask воркеры nginx не могли прочитать
  собственные страницы ошибок и файлы паролей. Права исправляются автоматически, добавлены проверка
  «Права доступа воркеров nginx» и исправление в один щелчок в Диагностике.
- Категория «Прочее» в журнале ошибок получила описание.
