# История версий

Обновление на новую версию: `sudo ./update.sh` из каталога с новой версией (подробно — в главе
[03](03-installation.md)). Перед обновлением делается резервная копия, при ошибке запуска выполняется откат.

## 1.8.0

**Новое**

- **Уведомления о событиях** ([11](11-alerts.md#уведомления-о-событиях)): сбой выпуска или продления сертификата,
  ошибка применения конфигурации (в том числе при автоприменении), перезапуск nginx сторожем, блокировка перебора
  пароля, вход администратора с нового адреса, сбой фоновой задачи или выгрузки копии — сразу в Telegram, Slack,
  Discord, почту или webhook. Выбор источников и уровня, одинаковые события не повторяются чаще заданного интервала
  (со счётчиком повторов), лимит 30 в час, глобальная тишина на время работ глушит и их.
- **Резервные копии в S3-хранилище** ([15](15-backup-versions.md#выгрузка-в-s3-хранилище)): AWS S3, Yandex Object
  Storage, VK Cloud, Selectel, Cloudflare R2, MinIO и другие. База сжимается gzip, по желанию оба файла шифруются
  (AES-256, пароль не показывается в интерфейсе), в хранилище остаётся N последних копий. Проверка хранилища с
  пояснением ошибок, список копий в хранилище, скачивание на сервер с расшифровкой и распаковкой. Подпись AWS SigV4 —
  без сторонних библиотек.
- **Права API-токенов** ([12](12-security.md#api-токены)): токен «только чтение» для мониторинга и Prometheus,
  оператора или администратора — не выше своей роли; при понижении пользователя токены теряют лишние права. Срок
  действия выбирается при создании. Токен больше не может создать другой токен.
- Диагностика: группа «Резервные копии» — давно не было ежедневной копии, выгрузка в хранилище не удалась или
  устарела, копии в хранилище не зашифрованы.
- Журнал «События»: новые записи — конфигурация не применена (с причиной), блокировка входа, вход с нового адреса.

**Исправления** (найдены сквозной проверкой на стенде: nginx убит, применение сломано, ACME-сервер выключен)

- Подсказка к ошибке продления «нет связи с ACME-сервером» говорила про ключ TSIG (слово «refused» совпадало с кодом
  DNS REFUSED) или про порт 80 — теперь объясняет, что недоступен сам центр сертификации.
- Сертификат своего ACME-сервера не продлевался после переключения центра в настройках: корневой сертификат
  ACME-сервера брался из текущих настроек. Теперь путь запоминается в сертификате.
- Если центр сертификации удалил аккаунт (или пересоздан свой ACME-сервер), продление падало с «Account not found»
  до ручного вмешательства. Теперь панель удаляет устаревшую запись certbot и повторяет выпуск с новым аккаунтом.
- Подсказка для недоступного DNS-сервера RFC 2136; «Проверить» у такой учётной записи проверяет и доступность
  сервера.
- Из события об ошибке nginx убран служебный префикс `PID#TID:`.
- Выбор источников в форме показывает названия («Сертификаты»), а не коды (`certs`).

Автотестов 112 (было 102): уведомления (фильтры, повторы, лимит, тишина, путь через API), права токенов,
подпись S3 сверяется с botocore, полный цикл выгрузки — против эмулятора S3 (moto).

## 1.7.0

**Новое**

- **DNS-проверка и wildcard-сертификаты** ([07](07-certificates.md#wildcard-сертификаты-examplecom)): сертификаты на
  `*.example.com` и для серверов, закрытых от интернета, выпускаются прямо из панели. Учётные записи DNS-провайдеров —
  Cloudflare, DigitalOcean, Linode, OVHcloud, Route 53, Google Cloud DNS, свой DNS-сервер (RFC 2136: BIND, PowerDNS,
  Knot, Windows DNS) и свои скрипты для любого провайдера. Панель показывает, установлен ли плагин certbot, и ставит
  его кнопкой; секреты хранятся в файлах с правами 600 и не показываются в интерфейсе.
- **Выбор центра сертификации** ([07](07-certificates.md#центр-сертификации)): Let's Encrypt, ZeroSSL, Google Trust
  Services или свой ACME-сервер (step-ca, Smallstep, Vault PKI) с привязкой аккаунта EAB и доверенным корневым
  сертификатом. Сертификат продлевается в том центре, где выпущен; центр виден в списке.
- Короткие сертификаты (сутки у step-ca, 6–45 дней у ACME-профилей) продлеваются за треть срока, а не за 30 дней —
  иначе они продлевались бы при каждой проверке. Сроки проверяются ежечасно (было — раз в 6 часов); после неудачного
  продления — пауза до 6 часов, чтобы не упираться в лимиты центра. Предупреждения диагностики и анализа, оповещение
  «Сертификат скоро истечёт» учитывают срок действия: для коротких сертификатов тревога — только если продление
  действительно опаздывает; оставшееся время показывается в часах.
- Диагностика: certbot установлен, но не запускается (сертификаты молча перестают продлеваться); не установлен
  плагин DNS-провайдера (кнопка «Установить плагин»); выбран центр без адреса или ключа EAB.
- Подсказки к ошибкам выпуска: TXT-запись не найдена, токен отклонён, зона не найдена, ошибки TSIG, EAB, TLS
  ACME-сервера.
- Экспорт и импорт переносят учётные записи DNS и ссылки сертификатов на них.
- Инструмент скриншотов сообщает адрес каждого ответа с ошибкой (раньше в консоли было только «404» без адреса).
- Автотестов 102 (было 90); все проходят на Python 3.9 и 3.13.

**Проверено**

- Сквозной тест `tools/acme_e2e.py` против тестового ACME-сервера Pebble и DNS-сервера BIND: выпуск с
  HTTP-проверкой, wildcard с DNS-проверкой через RFC 2136, подключение wildcard к сайту и проверка сертификата,
  который отдаёт nginx, продление с новым серийным номером, привязка EAB (HMAC-ключ скрыт в журнале).
  До этого выпуска путь Let's Encrypt проверялся только по частям.

**Исправления**

- Мастер нового сайта: регулярные выражения и `.example.com` больше не попадают в запрос сертификата; для
  wildcard-домена мастер сразу объясняет, что нужна DNS-проверка.

## 1.6.0

Выпуск посвящён проверке всего кода: новые автотесты (фаззинг всех маршрутов API, импорт конфигурации nginx,
сборщик статистики, оповещения, сертификаты, консоль `nmctl`) нашли и закрыли ошибки, перечисленные ниже.

**Безопасность**

- Политика входа проверяется сервером, а не только интерфейсом: пользователь с временным паролем и администратор
  без 2FA (при включённом «Требовать 2FA для администраторов») могут только смотреть и настраивать свой профиль;
  изменения, в том числе через API, и создание API-токена отклоняются с кодом 403 ([12](12-security.md)).
  Включить требование 2FA можно, только настроив 2FA себе.
- «Свои директивы»: оператор больше не может добавить директивы, которые читают или создают файлы от root или
  выполняют код (`include` произвольного файла, журналы вне `/var/log/nginx`, временные каталоги, Lua, Perl, njs) —
  раньше через `include /etc/shadow` и ошибку `nginx -t` можно было прочитать чужой файл, а через журнал в
  `/etc/cron.d` — выполнить команду от root. Наблюдатель больше не может запускать `nginx -t` для черновика
  сайта ([12](12-security.md#безопасность-сервиса-в-системе)).
- Код 2FA принимается один раз: повторно использовать подсмотренный код нельзя.
- Вход отвечает одинаково (и по тексту, и по времени) на неизвестное имя и на неверный пароль.
- Непредвиденная ошибка сервера больше не раскрывает подробности в ответе — только тип ошибки и где смотреть журнал.
- Финальная резервная копия при удалении (`uninstall.sh`) создавалась с правами 644 — теперь 600: в ней хеши
  паролей, секреты каналов и закрытые ключи. Копия делается после остановки сервиса, поэтому база в ней согласована.

**Исправления**

- Оповещения: правило без выбранных каналов отправляло уведомления во все каналы — теперь, как и описано, только в
  панель; в тексте уведомления вместо номера сайта — его название; пропуск данных (нет запросов, сайт выключен)
  больше не считается восстановлением и не порождает пары «Восстановлено → Сработало» ([11](11-alerts.md)).
- Импорт существующей конфигурации nginx падал на директивах без аргументов (например, `proxy_pass;` в шаблоне).
- Сборщик статистики: строка журнала с JSON неожиданной формы (не объект, вложенные значения, код ответа вне
  100–999) могла остановить разбор пачки — теперь она учитывается как ошибка разбора.
- `nmctl`: ошибки выводятся понятным текстом с кодом возврата 1 вместо трассировки Python; импорт полностью
  проверяет файл (в том числе записи пользователей) до изменения базы, повреждённый файл не меняет ничего
  ([14](14-cli-api.md)).
- `GET /api/requests/live` игнорировал параметр `seq`.
- Регулярный отчёт: в строке «Запросов: 12,3 тыс., …» точка сокращения превращалась в запятую.
- Дашборд: пока первая проверка бэкенда не прошла (сразу после запуска), карточка «Бэкенды» писала «все доступны» —
  теперь «проверяется: N».
- Журнал аудита: запись о действии над сотнями сайтов раздувала таблицу — теперь в записи не более 50 имён, а длинные
  детали в интерфейсе сворачиваются; у всех действий понятные подписи.
- WebSocket: неверное сообщение от браузера больше не обрывает соединение, фильтр живого журнала проверяется;
  ограничение доступа к панели по IP применяется и к WebSocket.
- Фоновые задачи (диагностика, сети стран, продление сертификатов, отчёты, автоматическая копия) выполняются
  независимо: сбой одной записывается в «События» и не откладывает остальные. Сбой записи истории проверок бэкендов
  больше не останавливает сами проверки.
- Python 3.9 (RHEL 8/9): примитивы asyncio создаются внутри цикла событий; весь набор тестов проходит на 3.9 и 3.13.
- Активные проверки бэкендов: задачи проверок теперь удерживаются до завершения (раньше теоретически могли быть
  удалены сборщиком мусора на середине проверки).

**Установка и диагностика**

- SELinux: диагностика проверяет метки всех портов, которые займёт nginx (сайты, HTTP/3, потоки, `stub_status`), и
  исправляет их одной кнопкой; ошибка `bind() … (13: Permission denied)` при применении получает пояснение
  ([10](10-diagnostics.md)).
- RHEL-семейство: EPEL для Oracle Linux и запасной источник EPEL; репозиторий nginx.org с
  `skip_if_unavailable=1`. Поддержка GeoIP ставится автоматически, если в каталоге данных уже есть база стран
  ([03](03-installation.md)).

**Документация и качество**

- Полный справочник REST API — все 116 методов с ролями и описанием — собирается из кода
  ([14](14-cli-api.md#все-методы)); описания попали и в Swagger UI.
- Автотесты следят, чтобы справочники в документации совпадали с кодом, а ссылки на разделы и картинки не были битыми.
- Автотестов 90 (было 61), покрытие кода 72% (было 57%); ruff, eslint и shellcheck — без замечаний; неиспользуемые
  импорты в интерфейсе убраны.

## 1.5.0

**Новое**

- **Доступность сайтов (SLA)** ([09](09-monitoring.md#доступность-сайтов-sla)): доля ответов без 5xx за 24 часа,
  7 и 30 дней, полоса по дням, дни ниже цели, худший день и бюджет ошибок для цели 99%–99,95%.
- **Нагрузка по дням недели и часам** ([09](09-monitoring.md#нагрузка-по-дням-недели-и-часам)): тепловая карта
  запросов, доли 5xx и времени ответа за 1, 4 или 12 недель; час пика и час минимума.
- Страница «Бэкенды»: поиск, фильтр «С проблемами», проблемные группы наверху, табличный вид для сотен серверов.

**Работа с сотнями сайтов** (проверено на 300 сайтах: применение 1,1 с, процессор панели в среднем 1,6%)

- Память под статистику последнего часа ограничена: счётчики трафика и времени хранятся только для строк топов.
  На нагрузке «20 сайтов × 2000 уникальных IP в минуту» — 154 МБ вместо 1 ГБ.
- Диагностика сворачивает однотипные проверки (DNS сотен доменов, серверы бэкендов) в одну строку со списком;
  DNS проверяется для всех доменов (раньше — только для первых 200), параллельно и с общим лимитом времени.
- Анализ объединяет одинаковые находки у многих сайтов в одну карточку со списком сайтов.
- Первые проверки новых бэкендов разносятся по времени, а не идут залпом.

**Исправления**

- Резервная копия восстанавливается один в один: при импорте с заменой потоки, правила и каналы оповещений
  сохраняют номера (раньше потоки и правила получали новые и отрывались от истории и ссылок); в режиме «добавить»
  ссылки правил на сайты и каналы, а также каналы регулярных отчётов переносятся на новые номера.
- Просмотр конфигурации: одинарные кавычки показывались как `&#39;` (например, в CSP `'self'`).
- Задержка у сервера с неудачной последней проверкой показывается прочерком, а не «0 мс».
- Тесты: полный цикл экспорта и импорта, доступность и тепловая карта, свёртка диагностики, память статистики,
  экранирование в подсветке конфигурации (через node).

## 1.4.0

**Новое**

- **Доступ к сайтам по странам** ([17](17-bans.md#доступ-по-странам)): запретить выбранные страны или разрешить
  только выбранные; исключения по IP, пропуск локальных сетей, ответ 403/444/451. Сети стран панель сама
  выбирает из базы GeoIP (GeoLite2 / DB-IP) и подключает в nginx через `geo` — без сторонних модулей. Проверки
  Let's Encrypt не ограничиваются. Вкладка «Страны» в «Блокировках IP»: состояние базы, сайты с правилами,
  отклонённые запросы по странам и сайтам; диагностика, два новых сценария анализа, метрика Prometheus.
  Обновлённая база подхватывается автоматически.
- **Массовые действия со списком сайтов** ([05](05-sites.md#массовые-действия)): включить, выключить,
  обслуживание, добавить или убрать метку, удалить — для нескольких сайтов сразу; `POST /api/sites/bulk`.
- Названия стран по-русски в аналитике, блокировках и журнале; выбор стран с поиском по названию.
- `update.sh --with-geoip` — добавить поддержку GeoIP при обновлении.

**Исправления и безопасность**

- Проверка значений, попадающих в конфигурацию nginx, усилена по результатам фаззинга всех полей: обратная косая
  черта и `#` в начале значения больше не ломают конфигурацию; хеш пароля Basic Auth проверяется по формату
  (раньше через API можно было дописать строку в файл паролей).
- Хеши паролей Basic Auth больше не отдаются в интерфейс и API: в данных сайта поле пустое, в версиях
  конфигурации и сравнениях вместо хеша — отпечаток.
- Проверка домена для Let's Encrypt (`/api/certs/selftest`) доступна оператору и администратору, а не наблюдателю.
- Ответы, отклонённые блокировками по IP и странам, не считаются нарушениями для автоблокировки и не завышают
  долю ошибок 4xx в анализе (признак `gb` в журнале доступа, учёт кодов отклонённых ответов).
- Добавлены автотесты: фаззинг генератора с проверкой `nginx -t`, обновление базы с версии 1.0.0, доступ по
  странам, массовые действия.

  бэкендов, CPU, памяти, диска и нагрузки; действуют и на цвет карточек, и на сценарии.
- **История проблем**: моменты обнаружения и устранения проблем с длительностью (вкладка «История» анализа,
  раздел «События»).
- Интеграционные тесты REST API (вход, CSRF, роли, токены, сайты, блокировки, анализ, отчёты, метрики,
  документация, WebSocket).

**Исправления**

- Копии, которые делают `update.sh` и `nmctl backup` (база, архив кода прежней версии, nginx.conf), больше не
  накапливаются без ограничений: хранится по 5 штук каждого вида (настраивается). Ручные копии из панели не
  удаляются.
- Числа в находках анализа и отчётах выводятся с разделителями разрядов и десятичной запятой.
- Диалоги и подсказки закрываются при переходе на другую страницу.
- Быстрый переход между разделами больше не может показать содержимое предыдущей страницы: если она ещё
  загружала данные, её запоздалый результат отбрасывается.
- `nmctl diag` больше не сообщает ложное «отставание обработки» журнала доступа, когда файл журнала крупнее 50 МБ.
